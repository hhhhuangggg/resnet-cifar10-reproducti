# 第六阶段：训练与评估闭环学习总结

## 一、本阶段完成了什么

前五个阶段已经准备好模型和数据。本阶段第一次让真实CIFAR-10经过
ResNet-20，并通过loss和反向传播修改网络参数。

完整训练闭环：

```text
DataLoader取batch
→ 图片和标签移动到GPU
→ 清除旧梯度
→ 模型前向传播
→ CrossEntropyLoss
→ 反向传播
→ SGD更新参数
→ 统计loss和accuracy
```

完整评估闭环：

```text
切换评估模式
→ 禁用梯度
→ 测试batch移动到GPU
→ 前向传播
→ 计算loss和accuracy
→ 不修改任何模型参数
```

本阶段只训练5个batch、评估3个batch，用于证明机制正确，没有运行完整
epoch或5轮实验。

## 三、EpochMetrics是什么

训练或评估结束后返回：

```python
@dataclass(frozen=True)
class EpochMetrics:
    loss: float
    accuracy: float
    correct: int
    samples: int
    batches: int
```

例如本次训练：

```text
loss=2.3725
accuracy=0.128125
correct=82
samples=640
batches=5
```

`frozen=True`表示结果创建后不能被意外修改。`accuracy=0.128125`就是
12.8125%。

## 四、第一步：从DataLoader取出batch

```python
for images, labels in train_loader:
    ...
```

默认形状：

```text
images：[128,3,32,32]，float32
labels：[128]，int64
```

images包含128张三通道图片；labels包含每张图片的正确类别编号。

## 五、第二步：移动到GPU

```python
images = images.to(device, non_blocking=True)
labels = labels.to(device, non_blocking=True)
```

DataLoader产生CPU Tensor，模型位于GPU时输入也必须位于同一GPU，否则
PyTorch会报设备不一致。

`non_blocking=True`与DataLoader的 `pin_memory=True` 配合时可以让CPU到
GPU传输更高效，但它不会改变数值。

## 六、第三步：切换训练模式

```python
model.train()
```

这句话不是“开始循环”，而是改变模型内部某些层的工作方式。

训练模式下BatchNorm：

- 使用当前batch统计量；
- 更新运行均值和方差；
- 保留反向传播需要的信息。

训练函数每次开始时主动调用，避免模型上一次评估后仍停留在eval模式。

## 七、第四步：清除旧梯度

```python
optimizer.zero_grad(set_to_none=True)
```

PyTorch默认会累积梯度：

```text
新grad = 旧grad + 当前batch的grad
```

普通mini-batch训练希望每个batch单独计算更新，所以每次forward前先清除
旧梯度。

`set_to_none=True`把grad设为None，而不是逐元素写0，通常更高效。

## 八、第五步：前向传播

```python
logits = model(images)
```

ResNet-20：

```text
输入：[128,3,32,32]
输出：[128,10]
```

每一行10个logit是10个类别的原始分数。它们：

- 可以为正数或负数；
- 不要求相加等于1；
- 不是概率；
- 分数最大位置是当前预测类别。

不在模型中手动softmax，因为CrossEntropyLoss内部会以更稳定的方式处理。

## 九、第六步：CrossEntropyLoss

```python
criterion = nn.CrossEntropyLoss()
loss = criterion(logits, labels)
```

输入要求：

```text
logits：[N,C]浮点数
labels：[N]int64类别编号
```

它会提高正确类别得分、压低错误类别得分。输出为一个标量Tensor。

十分类随机猜测的理论参考loss：

```text
-ln(1/10) ≈ 2.3026
```

但随机权重、BatchNorm、数据增强和不同batch会让实际初始loss上下波动。

## 十、第七步：反向传播

```python
loss.backward()
```

前向传播时PyTorch建立计算图。`backward()`从loss向前追溯：

```text
loss
→ fc
→ stage3
→ stage2
→ stage1
→ stem
```

并把“参数改变一点会让loss怎样变化”写入每个参数的 `.grad`。

关键区别：

```text
backward：计算梯度
step：根据梯度修改参数
```

只调用backward而不调用step，权重仍不会变化。

## 十一、第八步：SGD更新参数

```python
optimizer.step()
```

本次配置：

```python
torch.optim.SGD(
    model.parameters(),
    lr=0.1,
    momentum=0.9,
    weight_decay=0.0001,
)
```

### learning rate

决定每次沿更新方向走多远。太大可能震荡或发散，太小则学习缓慢。

### momentum

保留历史更新方向，类似带惯性的移动，有助于减少来回震荡。

### weight decay

抑制权重无限变大，是一种正则化方法。

简化更新概念：

```text
新参数 = 旧参数 - 学习率 × 优化方向
```

本阶段复制了训练前后的参数，确认至少一个参数发生变化，证明闭环确实
执行了更新。

## 十二、为什么顺序不能颠倒

正确顺序：

```text
zero_grad
→ forward
→ loss
→ backward
→ step
```

错误情况：

| 错误 | 后果 |
|---|---|
| 忘记zero_grad | 梯度跨batch意外累积 |
| 忘记backward | 没有当前batch梯度 |
| 忘记step | 参数永远不更新 |
| step放在backward前 | 当前batch无法用于本次更新 |
| 对测试集执行step | 测试数据泄漏进模型 |

## 十三、怎样计算accuracy

```python
predictions = logits.argmax(dim=1)
correct = (predictions == labels).sum().item()
```

形状：

```text
logits：[128,10]
argmax(dim=1)
→ predictions：[128]
```

累计全部正确数：

```python
accuracy = correct_sum / sample_sum
```

内部使用0～1，例如：

```text
0.128125 = 12.8125%
```

## 十四、为什么loss要按样本加权

CrossEntropyLoss默认返回当前batch平均loss。如果batch大小不同，不能把
各batch平均loss直接再平均。

正确：

```python
loss_sum += loss.item() * batch_samples
average_loss = loss_sum / total_samples
```

这样每张图片权重相同。测试使用2张和1张的不同大小batch，验证了这一点。

## 十五、训练模式和评估模式

训练：

```python
model.train()
```

评估：

```python
model.eval()
with torch.no_grad():
    ...
```

`model.eval()`控制BatchNorm等层；`no_grad()`控制Autograd，二者不能互相
替代。

评估函数不接收optimizer，因此接口层面就减少了错误更新测试集的机会。

## 十六、为什么评估使用no_grad

评估不需要更新模型：

```python
with torch.no_grad():
```

可以：

- 不建立反向传播图；
- 减少显存；
- 加快计算；
- 不产生新梯度。

本阶段复制了评估前后的全部参数，验证它们逐项完全相同。

## 十七、max_batches的作用

```python
max_batches=None
```

表示处理完整DataLoader。

```python
max_batches=5
```

表示处理5个batch后提前结束。

这不是论文训练设置，而是工程调试工具。先用少量数据验证整个链路，可以
避免完整训练后才发现错误。

## 十八、代码的训练循环

核心结构：

```python
model.train()

for batch in data_loader:
    images, labels = move_batch_to_device(batch, device)
    optimizer.zero_grad(set_to_none=True)
    logits = model(images)
    correct, samples = compute_batch_statistics(logits, labels)
    loss = criterion(logits, labels)
    loss.backward()
    optimizer.step()
```

实际代码还增加了形状、dtype、标签范围、NaN、无穷和空DataLoader检查。

## 十九、代码的评估循环

```python
model.eval()

with torch.no_grad():
    for batch in data_loader:
        images, labels = move_batch_to_device(batch, device)
        logits = model(images)
        loss = criterion(logits, labels)
        correct, samples = compute_batch_statistics(logits, labels)
```

没有：

```text
zero_grad

```

## 二十二、loss为什么没有要求连续下降

连续batch包含不同图片，训练集还有随机裁剪和翻转，因此每个batch难度
不同。五个batch内loss可能上下波动。

观察收敛要看：

- 完整epoch的平均loss；
- 多个epoch的趋势；
- 训练准确率和测试准确率；
- PlainNet与ResNet在相同设置下的曲线。

这些属于后续正式预实验。
