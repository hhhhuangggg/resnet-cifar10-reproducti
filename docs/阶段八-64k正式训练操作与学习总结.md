# 阶段八：64k Iteration 正式训练操作与学习总结

## 1. 这一阶段增加了什么

五轮预实验使用的是：

```text
训练5个epoch
学习率始终为0.1
```

它适合验证整条训练流程，却不是论文的正式日程。第八阶段增加：

```text
严格训练64,000次参数更新
完成32,000次后将学习率从0.1降到0.01
完成48,000次后将学习率从0.01降到0.001
完成第64,000次更新后立即结束
```

## 2. Iteration 与 Epoch 的区别

一个 iteration 表示模型处理一个训练 batch，并执行一次：

```python
optimizer.step()
```

一个 epoch 表示训练集中的全部图片大约被处理一遍。

当前设置：

```text
训练图片：50,000张
batch size：128
每个epoch：ceil(50000 / 128) = 391个batch
```

所以一个完整 epoch 通常包含391个 iterations。

论文的64k日程约为：

```text
163个完整epoch = 63,733 iterations
最后部分epoch = 267 iterations
合计 = 64,000 iterations
```

程序根据实际 DataLoader 长度计算，不把这些数字写死。

## 3. 学习率边界

严格语义是：

| 参数更新编号 | 使用的学习率 |
|---:|---:|
| 1～32,000 | 0.1 |
| 32,001～48,000 | 0.01 |
| 48,001～64,000 | 0.001 |

代码记录的是“已经完成多少次更新”：

```text
completed=31,999 → 下一次仍使用0.1
completed=32,000 → 下一次改用0.01
completed=48,000 → 下一次改用0.001
completed=64,000 → 停止
```

这能避免常见的提前或延后一个 batch 的错误。

## 4. 为什么仍按 Epoch 测试

训练停止条件使用 iteration，但每完成一轮训练集仍评估一次完整测试集：

```text
训练约391个batch
→ 测试10,000张图片
→ 写CSV和TensorBoard
→ 保存checkpoint
```

最后267个batch完成后也会进行最终测试。

测试不计算梯度，不更新模型。根据五轮实验实测，一次测试约1.9秒，整个正式日程额外增加约5分钟。

## 6. CSV 新字段

paper `history.csv` 每次评估写一行：

| 字段 | 含义 |
|---|---|
| `epoch` | 当前数据轮次编号 |
| `iteration` | 已完成的参数更新总数 |
| `train_batches` | 本轮实际训练的batch数 |
| `is_partial_epoch` | 是否为最后不足一轮的数据 |
| `train_loss` | 本轮训练平均loss |
| `train_accuracy` | 本轮训练准确率 |
| `test_loss` | 完整测试集loss |
| `test_accuracy` | 完整测试集准确率 |
| `learning_rate` | 下一次更新将使用的学习率 |
| `elapsed_seconds` | 本轮训练加测试耗时 |
| `best_test_accuracy` | 当前历史最佳测试准确率 |

最终一行应该满足：

```text
iteration = 64000
is_partial_epoch = True
```

## 7. TensorBoard 怎么看

paper 日程使用 iteration 作为横轴。

重点观察：

- `Loss/train`：训练优化是否持续推进；
- `Loss/test`：泛化损失；
- `Accuracy/train`：训练集学习程度；
- `Accuracy/test`：测试集泛化表现；
- `LearningRate`：32k、48k的阶梯下降；
- `Progress/epoch`：iteration大约对应第几轮；
- `Time/epoch_seconds`：每轮耗时。

在32k和48k附近重点比较：

```text
学习率下降前，loss是否震荡或下降变慢
学习率下降后，loss是否继续下降
测试accuracy是否出现新的提升
```

## 12. 中断与恢复

按 `Ctrl+C` 时：

- 当前没有完成的 epoch 不保存；
- 上一个已评估 epoch 的 `latest.pt` 保留；
- 最多损失当前约20秒训练；
- 恢复后重新执行这一轮。

PlainNet 恢复：

```bat
python train.py --model plain20 --schedule paper --resume "outputs\plain20\seed42_paper64k\latest.pt"
```

ResNet 恢复：

```bat
python train.py --model resnet20 --schedule paper --resume "outputs\resnet20\seed42_paper64k\latest.pt"
```

checkpoint 会恢复：

- 模型参数；
- SGD momentum状态；
- global iteration；
- 当前学习率；
- history；
- 最佳准确率；
- Python、NumPy、PyTorch和CUDA随机状态。

## 13. Git 如何保护五轮版本

稳定五轮代码在：

```text
main
```

正式日程代码在：

```text
paper-64k-schedule
```

查看：

```bat
git branch -vv
git log --oneline --graph --decorate --all
```

切回五轮版本：

```bat
git switch main
```

回到正式日程：

```bat
git switch paper-64k-schedule
```

数据集、`.pt` 和 TensorBoard event 被 `.gitignore` 排除，切换分支不会删除这些本地文件。

## 14. 本阶段要学会什么

完成本阶段后，应能解释：

1. epoch和iteration为什么不是同一个概念；
2. 为什么论文用iteration确定学习率节点；
3. 第32,001次更新为什么才使用0.01；
4. 为什么64k不能简单等同于164个完整epoch；
5. 测试为什么不改变权重；
6. checkpoint为什么必须保存optimizer和global iteration；
7. TensorBoard横轴为什么改成iteration；
8. PlainNet与ResNet正式比较必须控制哪些变量。

正式训练不是简单“跑得更久”，而是严格执行论文规定的优化轨迹，并保存足够信息让结果可检查、可恢复、可比较。
