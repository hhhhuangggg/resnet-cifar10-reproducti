# 阶段七：训练系统学习总结

## 1. 这一阶段解决了什么问题

前六阶段已经分别具备：

- `models/`：PlainNet 和 ResNet 网络结构；
- `data.py`：CIFAR-10 下载、预处理、数据增强和 DataLoader；
- `engine.py`：单个 epoch 的训练与评估算法；
- `train.py`：命令行参数和实验配置。

但这些组件此前还没有形成一条能够直接运行的完整训练流水线。第七阶段的核心工作，是让 `train.py` 成为总指挥：

```text
读取参数
→ 检查GPU和实验目录
→ 固定随机种子
→ 创建数据、模型、损失函数和优化器
→ 循环执行训练与测试
→ 保存曲线、表格和模型状态
```

## 2. 四个主要文件如何协作

| 文件 | 职责 | 不负责什么 |
|---|---|---|
| `models/*.py` | 定义网络层及前向传播 | 不读取数据，不执行反向传播 |
| `data.py` | 把 CIFAR-10 变成可迭代 batch | 不更新模型权重 |
| `engine.py` | 完成一个 epoch 的训练或评估 | 不创建实验目录，不写 TensorBoard |
| `train.py` | 组织完整实验并保存结果 | 不重复定义网络和数据变换 |

这种拆分的价值是：数学计算、数据处理和实验管理能够分别测试。以后更换模型时，不需要重写训练循环；以后更换日志方式时，也不需要改反向传播公式。

## 3. `engine.py` 新增了什么

新增不可变数据类：

```python
@dataclass(frozen=True)
class BatchProgress:
    batch: int
    loss: float
    accuracy: float
    correct: int
    samples: int
```

它表示“从本轮开始到当前 batch 为止”的累计状态。

例如训练到第 10 个 batch：

- `batch=10`：已经处理 10 个 batch；
- `samples`：已经处理的图片总数；
- `correct`：其中预测正确的总数；
- `accuracy=correct/samples`；
- `loss`：按样本数加权的累计平均 loss。

`train_one_epoch()` 与 `evaluate()` 增加可选回调：

```python
on_batch_end(progress)
```

`engine.py` 只产生数据，不知道 tqdm 的存在。`train.py` 收到数据后更新进度条。这叫“计算与显示解耦”。

## 4. 为什么要固定随机种子

训练中有多处随机性：

- 模型权重初始化；
- 训练集 shuffle；
- 随机裁剪；
- 随机水平翻转；
- CUDA 中的部分计算。

`set_random_seed(42)` 同时设置 Python、NumPy、PyTorch CPU 和 CUDA 随机状态，并使用：

```python
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

这样做是为了让 PlainNet 与 ResNet 的比较更可追踪。它不保证不同机器上的每个小数位都完全相同，但能显著减少无关随机差异。

## 5. 为什么 CUDA 不可用时不能自动改用 CPU

如果命令写了：

```text
--device cuda
```

却自动退回 CPU，用户可能以为 GPU 正在训练，只觉得速度异常缓慢。因此 `resolve_device()` 会直接报错，让设备问题在训练开始前暴露。

## 6. 为什么要保护实验目录

默认实验路径为：

```text
outputs/<model>/seed42_5epochs
runs/<model>/seed42_5epochs
```

如果其中已有文件，新实验会拒绝启动。这样可以避免：

- 新 CSV 覆盖旧结果；
- 新 checkpoint 覆盖旧模型；
- 两次 TensorBoard 曲线混到同一个 run；
- 对比时不知道结果来自哪次实验。

若确实要重新训练，可指定不同的 `--run-name`。

## 7. 一个完整 epoch 内发生什么

每轮严格按以下顺序执行：

1. `model.train()` 开启训练模式；
2. 从训练 DataLoader 取出 batch；
3. 图片与标签移动到 GPU；
4. 模型前向传播，得到 `[N, 10]` logits；
5. CrossEntropyLoss 计算分类损失；
6. `optimizer.zero_grad()` 清除旧梯度；
7. `loss.backward()` 计算当前梯度；
8. `optimizer.step()` 更新权重；
9. 完成全部训练 batch 后得到训练集指标；
10. `model.eval()` 并关闭梯度；
11. 遍历测试集，得到测试指标；
12. 形成这一轮的历史记录；
13. 写 CSV、TensorBoard 和 checkpoint。

只有步骤 7 和 8 会学习权重。测试阶段没有 `backward()` 和 `step()`，因此不会改变模型。

## 8. tqdm、终端总结和 TensorBoard 的区别

| 工具 | 更新频率 | 主要用途 |
|---|---|---|
| tqdm | 每个 batch | 判断程序是否还在运行、当前 loss/accuracy |
| 终端 epoch 总结 | 每轮一次 | 快速读取本轮完整训练与测试结果 |
| TensorBoard | 每轮一次 | 对比曲线趋势和多个实验 |
| `history.csv` | 每轮一次 | 精确保存数值，便于表格分析 |

tqdm 中的数据是本轮运行平均值，因此会随 batch 变化；TensorBoard 只记录完整 epoch，避免中断时留下半轮数据点。

## 9. 四个输出文件有什么不同

### `config.yaml`

保存本次实验的模型、数据处理、超参数、设备和路径。它回答：“这组结果是在什么条件下产生的？”

### `history.csv`

每行代表一个完整 epoch，固定包含：

```text
epoch
train_loss
train_accuracy
test_loss
test_accuracy
learning_rate
elapsed_seconds
best_test_accuracy
```

### `latest.pt`

保存最近一个完整 epoch。主要用于中断后继续训练。

### `best.pt`

只在测试准确率严格超过历史最佳值时更新。主要用于保留泛化表现最好的模型，而不是最后一个模型。

## 10. checkpoint 为什么不只保存模型权重

为了真正继续训练，还需要保存：

- 模型参数；
- 优化器状态；
- 已完成的 epoch；
- 历史最佳准确率；
- 完整 history；
- 实验配置；
- Python、NumPy、PyTorch 和 CUDA 随机状态。

SGD 使用 momentum 时，优化器内部保存“历史速度”。如果只恢复模型权重而不恢复优化器，后续轨迹就不再是原实验的延续。

## 11. 为什么使用原子写入

保存过程采用：

```text
先写 latest.pt.tmp
→ 确认写完
→ 替换 latest.pt
```

如果电脑在写入中途断电，旧的完整文件仍然存在；不会直接把唯一的 checkpoint 写成半个损坏文件。YAML 和 CSV 也采用相同思想。

## 12. Ctrl+C 后实际保留什么

恢复边界是“完整 epoch”：

- 在第 3 轮中间中断：保留第 2 轮末尾的状态；
- 在第 1 轮中间中断：没有完整 checkpoint，需要重新开始；
- 不保存半轮，是因为半轮恢复还要记录 sampler 顺序和 batch 位置，会显著增加复杂度。

## 13. 第七阶段的测试策略

自动测试不运行五轮真实 CIFAR-10，而是使用：

- 小模型；
- 内存假数据；
- 假 TensorBoard writer；
- 临时实验目录；
- 受控的训练/测试指标。

它验证的是程序逻辑。最后再用真实 ResNet-20、真实 CIFAR-10 和 GPU 各跑一个 batch，验证所有真实组件能够连通。

这种组合比每次都跑五轮更快：

```text
大量快速单元测试
+ 少量真实GPU冒烟
+ 用户正式实验
```

## 14. 你在正式训练中要重点理解什么

不要只看最终准确率，还要观察：

1. loss 是否从接近随机分类的状态下降；
2. 训练 accuracy 是否持续上升；
3. 测试 accuracy 是否同步提高；
4. 训练与测试曲线之间的差距；
5. PlainNet-20 与 ResNet-20 在相同条件下的收敛速度；
6. 五轮是否只够证明流程有效，而不足以复现论文最终精度。

第七阶段真正要学会的不是“一条训练命令”，而是理解从数据进入网络，到梯度更新，再到实验结果可追踪、可恢复、可比较的完整闭环。
